# Architecture

Next.js App Router / React Server Components; Node runtime for AI and PDF routes. Route group `(workspace)` authenticates server-side; each API separately calls `auth.getUser()`. Supabase SSR cookies are refreshed by Next.js `proxy.ts`. Auth actions use Next's same-origin protections; mutating JSON/PDF APIs explicitly verify Origin against `NEXT_PUBLIC_SITE_URL`.

- `src/app`: public landing/auth/pricing, private dashboard/tools/settings, API handlers.
- `src/components/ui/button.tsx`: shadcn-style CVA + Radix Slot primitive. Tailwind v4 and CSS design tokens; Motion respects reduced motion; Sonner toasts.
- `src/lib/supabase/server.ts`: user-scoped, cookie-backed client; `admin.ts`: server-only service role.
- `supabase/migrations`: tables, RLS, least-privilege grants, new-account trigger, serialized reservations.
- `src/lib/limits.mjs`: bounded streaming reader shared with executable Node tests.

## AI lifecycle

1. Verify origin, real Supabase user, byte limit and Zod schema; verify ownership of conversation/document through RLS.
2. Compute SHA-256 of canonical validated input and reserve a request UUID in PostgreSQL. A profile row lock serializes requests across Vercel instances.
3. Check `(user_id, request_id)` before limits. Identical completed request returns saved result; pending/failed/conflicting keys return 409. A UUID cannot spend quota twice.
4. Enforce 5 new accepted requests per minute and 15 pending/completed requests per UTC day. All plans currently share Free's limit. No client can change usage or subscriptions.
5. OpenAI has 45s timeout, no SDK automatic retries, 1,800 output tokens. Chat context: at most 12 recent messages / 18,000 characters plus current prompt. PDF: at most 24,000 extracted characters.
6. `complete_ai_request` writes chat messages and completed quota/result in the same database transaction. Known failures mark failed and release daily quota. Stale reservations become failed on the next claim after 5 minutes. A crash can leave a temporary reservation; a provider may bill a request whose response was lost. No exactly-once provider billing is promised.

Non-streaming AI responses deliberately permit atomic persistence before displaying success. The client shows skeletons and pending state. Streaming can be added after designing cancellation, retry and durable finalization semantics.

## PDF boundary

Raw application/pdf uploads avoid buffering multipart metadata. UI and API limit to 4 MiB (below Vercel's 4.5 MB ingress limit). Validate MIME and `%PDF-` bytes, then require successful parser output. Parse in a terminable Node worker with 96 MiB old-generation heap and 12s timeout; this is a resource guard, not a complete OS sandbox. PDF.js evaluation is disabled; no embedded JavaScript runs. No URL inputs or file-path inputs accepted. Max 80 pages, process first 20 pages, retain first 24,000 chars. No OCR, embeddings, full-document search or retrieval claims. Display scope with every selected document. Runtime/package behavior still needs deployment validation.

PDF upload attempts are limited in PostgreSQL to 3/minute, 20/day and 20 retained documents. Reservations protect parsing concurrency/rate; implement stronger global admission and malware scanning before opening to high-volume untrusted traffic. Source PDFs are discarded. Parsed text remains in `documents` until deleted.

## Data lifecycle

Conversation deletion cascades messages; document deletion removes extracted text. AI results (including Writer/PDF output) remain in `usage_records.result`, even after source deletion, and are user-readable through RLS. They support idempotent replay. Default migration does not schedule retention cleanup or implement account deletion. Operator must set a retention policy, delete old usage records after its retry/audit window and document Supabase backups/OpenAI retention before launch. Do not upload regulated documents without the appropriate provider agreements.

## Known validation limits

No fake data or demo bypass is used inside protected routes. Supabase must be configured and migration applied. A successful static test does not prove authentication, worker parser, RLS or provider integrations; see TASKS.md for evidence. Dependency lockfile was generated by a successful npm installation and npm ci was exercised. Public-page desktop/mobile browser checks, PDF worker tests and embedded PostgreSQL tests passed locally; external Supabase/OpenAI integrations remain unverified.
